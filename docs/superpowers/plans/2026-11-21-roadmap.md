# Radio Station Manager — Roadmap

Spec: `docs/2026-11-21-radio-station-manager-design.md`

The design spans several subsystems. Each milestone gets its own plan and ends in working,
testable software. Each plan is written when the previous milestone is done, so it can build
on the interfaces that actually exist.

| # | Milestone | Ends with | Spec sections |
|---|---|---|---|
| **M1** | **Scheduling core** (plan: `2026-11-21-m1-scheduling-core.md`) | `radio-cli plan station.toml` prints the merged 24 h timeline with start times and fixed-event fits | 6.2, 6.3, 6.6, 6.15 (locks) |
| M1.5 | Rules as scripts: rquickjs evaluates each playlist's rules script into typed `Rule` / `PickOrder` data; the UI's Script tab becomes live | Editing a rules script by hand changes the plan | 6.6, 6.8 |
| M2 | Audio engine: decks, streaming file decode, mixer, buses, R128 gain, local output, commands scheduled to the sample, offline renderer | Plays an M1 timeline on the sound card; the offline render matches the estimates to within a few ms | 6.4 (files), 6.5, 6.10, 6.13 |
| M3 | Station engine: command API, SQLite persistence, as-played log, crash resume, control socket, CLI + MCP | A headless station runs on its own, survives `kill -9`, and is controlled from the CLI / MCP | 6.2, 6.11, 6.14 (socket) |
| M4 | Desktop UI (egui): decks, two-pane playlist, playlist / rule editor, library, modes | The full operator UI on Windows, Linux and macOS | 6.12, 6.15 |
| M5 | Live inputs, internet streams, Icecast output | Live / stream / show items play; the Icecast mount works, with metadata | 6.4, 6.9 |
| M6 | Cartwall and JavaScript (rquickjs) | Carts over the air with ducking; event-hook scripts with time and memory limits | 6.7, 6.8 |
| M7 | Reliability: silence detector, fallback playlist, webhook alarms, 24 h soaks | Release candidate | 6.13, 6.14 |

M2 and M3 can be built at the same time once M1 is done (they meet only at the command
types). M4 needs M3. M5 and M6 need M2 and M3.
