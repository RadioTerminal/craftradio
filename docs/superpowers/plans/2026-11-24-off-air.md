# Off Air Switch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One saved On air / Off air switch that stops the Icecast push and WebRTC, confirmed by pressing twice, animated in the GUI.

**Architecture:** A setting `air.on_air` (default true) changed with `settings.set`. Playout reads it every tick: it tells the running Icecast worker to go off or on air (the worker keeps its tap, so it can reconnect), and it adds it to WebRTC's on/off rule. The view carries `on_air`, the adapter words the strips, the GUI draws an armed, animated button.

**Tech Stack:** Rust, egui, rtrb, the existing `radio-stream` Icecast client.

**Spec:** `docs/superpowers/specs/2026-11-24-off-air-design.md`

## Global Constraints

- AGENTS.md is binding: commands for every change (rule 6), no placeholder shown as success (rule 7), theme tokens only (rule 8), keyboard and words not only colour (rule 10), no `allow`, no panics in non-test code, tests in `tests/it/` per crate, `jiff` for time.
- Run cargo as `mise exec -- cargo …`; fmt, test and clippy `-D warnings` for each crate changed.
- The setting is part `air`, key `on_air`, a JSON bool; absent means on air.
- Off air never takes one press in the GUI, whatever the deck preference "Confirm a cut of the item on air" says. A `settings.set` from the CLI, MCP or a script switches at once.
- Words: the strips and status bar say `Off air`; the armed button says `Press again to go off air` / `Press again to go on air`; while reconnecting it says `Going on air…`.

## Review Focus

1. Off air while Icecast is retrying (server down): it must stop retrying, not keep dialling.
2. A quick off → on → off before Icecast connects: the last state wins, no stray connection.
3. Starting saved off air: no connection attempt at all, not even one before the first tick.
4. The Icecast tap while off air: frames are drained, so the mixer never blocks and on air does not replay seconds of old audio.
5. WebRTC with `webrtc_always` (the headless `--webrtc` flag): off air still stops it.

### Task 1: The Icecast worker goes off and on air

**Files:**
- Modify: `crates/stream/src/output.rs` (`Control`, `IcecastHandle`, `IcecastClient::start_*`, the worker loop and `send`)
- Test: `crates/stream/tests/it/` (a new module `off_air.rs`, registered in `main.rs`; reuse the test Icecast server the existing tests use)

**Interfaces:**
- Produces: `IcecastHandle::set_on_air(&self, on: bool)`; `StreamStatus::OffAir` (new variant); `IcecastClient::start_metered(cfg, frames, meter)` keeps its signature and starts on air; `IcecastClient::start_metered_off_air(cfg, frames, meter)` starts off air without dialling.

- [ ] **Step 1: Write the failing tests:** `off_air_closes_the_source_and_on_air_reconnects` (a test server sees the source connect, then leave after `set_on_air(false)` within the test patience, `status()` becomes `OffAir`; after `set_on_air(true)` it connects again and the status becomes `Connected`); `starting_off_air_never_dials` (the server sees no connection for a second, status is `OffAir`); `off_air_while_retrying_stops_retrying` (no server listening: status leaves `Retrying` for `OffAir` and no further connection attempt reaches a server started afterwards until on air); `off_air_drains_the_tap` (fill the producer side for two seconds while off air; on air, the first audio the server gets is from after the switch: write a marker tone only after on air and assert the first decoded second holds it).
- [ ] **Step 2: Run them, expect failures** (`set_on_air` not defined).
- [ ] **Step 3: Implement.** `Control::OnAir(bool)`. Off air: the worker leaves `send` (closing the connection), sets `OffAir`, and while off air pops and discards frames every 20 ms and blocks on the control channel with that timeout; retry delays also wake on control messages. On air: it resets the retry delay and connects. Every `match` on `StreamStatus` in the workspace gets the new arm (`crates/ui-engine/src/outputs.rs` words it `Off air`, not live).
- [ ] **Step 4: Run the stream tests, expect pass.**
- [ ] **Step 5: Commit** ("The Icecast source can go off air and back on without restarting").
